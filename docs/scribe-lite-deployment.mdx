Deploy Scribe as a single Docker container with no GPU requirements. Scribe Lite bundles all services into one image, managed by supervisord.

> **One-click platform deployments**: For platform-specific guides (Fly.io, Railway, Render, etc.), see the [scribe-lite-deploy repository](https://github.com/blastre/scribe-meetbot).

## Overview

**Why Scribe Lite?**

- **Single container** — All services bundled, no multi-service orchestration
- **Stateless** — All data stored in your database; easy to redeploy
- **No GPU required** — Uses the Scribe remote transcription service
- **Built-in Redis** — No external Redis needed (optional external Redis supported)
- **Interactive bots** — TTS (text-to-speech) and virtual camera included

### Included Services

Scribe Lite runs the following services internally via supervisord:

| Service | Internal Port | Description |
|---------|--------------|-------------|
| API Gateway | 8056 | Main entry point (the only exposed port) |
| Admin API | 8057 | User and API token management |
| Meeting API | 8080 | Bot orchestration + transcription pipeline |
| Runtime API | 8090 | Container lifecycle — process backend |
| Dashboard | 3000 | Next.js web UI |
| Redis | 6379 | Built-in message broker |
| Xvfb | — | Virtual display for headless browsers |
| PulseAudio | — | Audio server for TTS playback |

All internal services communicate over `localhost`. Only port **8056** is exposed externally.

## Quick Start

### Production: Remote Database

```bash
docker run -d \
  --name scribe \
  -p 8056:8056 \
  -e DATABASE_URL="postgresql://user:password@your-db-host:5432/scribe" \
  -e DB_SSL_MODE="require" \
  -e ADMIN_API_TOKEN="your-secret-admin-token" \
  -e TRANSCRIPTION_SERVICE_URL="https://transcription-service:8000/v1/audio/transcriptions" \
  -e TRANSCRIPTION_SERVICE_TOKEN="your-transcription-api-key" \
  scribe/scribe-lite:latest
```

> **Production:** Use immutable tags (e.g., `0.10.0-260405-0108`) instead of `:latest` for reproducible deployments.

### Development: Local Database

```bash
# Create network
docker network create scribe-network

# Start PostgreSQL
docker run -d \
  --name scribe-postgres \
  --network scribe-network \
  -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=your_password \
  -e POSTGRES_DB=scribe \
  -p 5432:5432 \
  postgres:latest

# Start Scribe Lite
docker run -d \
  --name scribe \
  --network scribe-network \
  -p 8056:8056 \
  -e DATABASE_URL="postgresql://postgres:your_password@scribe-postgres:5432/scribe" \
  -e ADMIN_API_TOKEN="your-secret-admin-token" \
  -e TRANSCRIPTION_SERVICE_URL="https://transcription-service:8000/v1/audio/transcriptions" \
  -e TRANSCRIPTION_SERVICE_TOKEN="your-transcription-api-key" \
  scribe/scribe-lite:latest
```

<Info>
The container automatically runs database migrations on startup. Fresh databases are initialized with the full schema.
</Info>

## Environment Variables

### Required

<ResponseField name="DATABASE_URL" type="string" required>
  PostgreSQL connection string. Supports both `postgresql://` and `postgres://` schemes.

  Example: `postgresql://user:pass@host:5432/scribe`

  Alternatively, set individual variables: `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`.
</ResponseField>

<ResponseField name="ADMIN_API_TOKEN" type="string" required>
  Secret token for [admin operations](self-hosted-management) (creating users, minting API tokens).
</ResponseField>

<ResponseField name="TRANSCRIPTION_SERVICE_URL" type="string" required>
  Transcription service endpoint.

  Default: `https://transcription-service:8000/v1/audio/transcriptions`
</ResponseField>

<ResponseField name="TRANSCRIPTION_SERVICE_TOKEN" type="string" required>
  API key for the transcription service (Deepgram or Groq).
</ResponseField>

### Database

You can use `DATABASE_URL` or individual variables. If both are provided, `DATABASE_URL` takes precedence.

<ResponseField name="DB_HOST" type="string" default="localhost">
  PostgreSQL hostname.
</ResponseField>

<ResponseField name="DB_PORT" type="string" default="5432">
  PostgreSQL port.
</ResponseField>

<ResponseField name="DB_NAME" type="string" default="scribe">
  Database name.
</ResponseField>

<ResponseField name="DB_USER" type="string" default="postgres">
  Database user.
</ResponseField>

<ResponseField name="DB_PASSWORD" type="string">
  Database password.
</ResponseField>

<ResponseField name="DB_SSL_MODE" type="string" default="disable">
  SSL mode for database connections. Set to `require` for cloud-hosted databases (Supabase, Neon, AWS RDS, etc.).
</ResponseField>

### Redis

Scribe Lite includes a built-in Redis server. If `REDIS_HOST` is `localhost` or unset, the internal Redis is used automatically. To use an external Redis, set `REDIS_HOST` to your Redis server address.

<ResponseField name="REDIS_HOST" type="string" default="localhost">
  Redis hostname. Set to an external address to use external Redis instead of the built-in server.
</ResponseField>

<ResponseField name="REDIS_PORT" type="string" default="6379">
  Redis port.
</ResponseField>

<ResponseField name="REDIS_URL" type="string">
  Full Redis URL. If provided, individual Redis vars are parsed from it.

  Example: `redis://user:password@redis-host:6379/0`
</ResponseField>

### Interactive Bots (TTS & Virtual Camera)

<ResponseField name="TTS_SERVICE_URL" type="string" default="http://127.0.0.1:8059">
  Internal local TTS service URL used by voice-agent bots. Scribe Lite wires this automatically.
</ResponseField>

<ResponseField name="PIPER_DEFAULT_VOICES" type="string" default="major">
  Piper voices to prepare on startup. `major` prepares the release-supported major language set for `voice: "auto"`.
</ResponseField>

<ResponseField name="PIPER_LOAD_VOICES" type="string">
  Optional comma-separated subset of prepared Piper voices to keep loaded in memory.
</ResponseField>

No OpenAI API key is required for the default `/speak` path. Text requests use the local Piper-backed TTS service with `provider: "piper"` and `voice: "auto"`. Pre-rendered audio requests (`audio_url` or `audio_base64`) bypass synthesis and are decoded by the bot before playback through the same virtual microphone.

### Recording Storage

<ResponseField name="STORAGE_BACKEND" type="string" default="local">
  Recording storage backend: `local`, `minio`, or `s3`.
</ResponseField>

<ResponseField name="LOCAL_STORAGE_DIR" type="string" default="/var/lib/scribe/recordings">
  Directory for local recording storage. Mount a volume here for persistence.
</ResponseField>

<Accordion title="S3 / MinIO storage variables">

For `STORAGE_BACKEND=s3`:

| Variable | Default | Description |
|----------|---------|-------------|
| `AWS_REGION` | `us-east-1` | AWS region |
| `AWS_ACCESS_KEY_ID` | — | AWS access key |
| `AWS_SECRET_ACCESS_KEY` | — | AWS secret key |
| `S3_BUCKET` | — | S3 bucket name |
| `S3_ENDPOINT` | — | Custom S3 endpoint (for non-AWS providers) |
| `S3_SECURE` | `true` | Use HTTPS for S3 connections |

For `STORAGE_BACKEND=minio`:

| Variable | Default | Description |
|----------|---------|-------------|
| `MINIO_ENDPOINT` | — | MinIO server endpoint (e.g., `minio:9000`) |
| `MINIO_ACCESS_KEY` | — | MinIO access key |
| `MINIO_SECRET_KEY` | — | MinIO secret key |
| `MINIO_BUCKET` | `scribe-recordings` | MinIO bucket name |
| `MINIO_SECURE` | `false` | Use HTTPS for MinIO connections |

</Accordion>

### Transcription

<ResponseField name="WHISPER_BACKEND" type="string" default="remote">
  Transcription backend. Use `remote` to route audio to the Scribe transcription service (recommended). Use `faster_whisper` for local CPU-based transcription (slow, development only).
</ResponseField>

<ResponseField name="WHISPER_MODEL_SIZE" type="string" default="tiny">
  Whisper model size when using local transcription (`WHISPER_BACKEND=faster_whisper`). Options: `tiny`, `base`, `small`, `medium`.
</ResponseField>

<ResponseField name="SKIP_TRANSCRIPTION_CHECK" type="string" default="false">
  Set to `true` to skip the startup connectivity check to the transcription service. The URL and API key are still required but won't be validated at startup.
</ResponseField>

### Logging

<ResponseField name="LOG_LEVEL" type="string" default="info">
  Log level for all services. Options: `debug`, `info`, `warning`, `error`.
</ResponseField>

## Health Check

The container includes a built-in health check that polls the API Gateway:

```
GET http://localhost:8056/docs
```

- **Interval:** 30s
- **Timeout:** 10s
- **Start period:** 90s (allows services to initialize)
- **Retries:** 3

Use this with your orchestrator's health check mechanism:

```bash
# Check container health
docker inspect --format='{{.State.Health.Status}}' scribe
```

## Recording Storage

For production, use object storage so recordings persist across container restarts:

```bash
docker run -d \
  --name scribe \
  -p 8056:8056 \
  -e STORAGE_BACKEND=s3 \
  -e AWS_ACCESS_KEY_ID="your-key" \
  -e AWS_SECRET_ACCESS_KEY="your-secret" \
  -e S3_BUCKET="scribe-recordings" \
  -e AWS_REGION="us-east-1" \
  -e DATABASE_URL="postgresql://user:pass@host/scribe" \
  -e ADMIN_API_TOKEN="your-admin-token" \
  -e TRANSCRIPTION_SERVICE_URL="https://transcription-service:8000/v1/audio/transcriptions" \
  -e TRANSCRIPTION_SERVICE_TOKEN="your-api-key" \
  scribe/scribe-lite:latest
```

> **Production:** Use immutable tags (e.g., `0.10.0-260405-0108`) instead of `:latest`.

For local development, mount a volume:

```bash
docker run -d \
  -v scribe-recordings:/var/lib/scribe/recordings \
  ...
```

For the full storage matrix, see [Recording storage](recording-storage).

## Build from Source

To build the image locally from the Scribe repository:

```bash
git clone https://github.com/blastre/scribe-meetbot.git
cd scribe/deploy/lite
make build
```

This produces a `scribe-lite:dev` image. See `make help` for additional commands (`push`, `set-latest`, etc.).

## Database Setup

<Accordion title="Supabase">
1. Create a project at [supabase.com](https://supabase.com)
2. Click **Connect** on the project page
3. Select method: **Session pooler**
4. Copy the connection string
5. Set `DB_SSL_MODE=require`
</Accordion>

<Accordion title="Neon">
1. Create a project at [neon.tech](https://neon.tech)
2. Copy the connection string from the dashboard
3. Set `DB_SSL_MODE=require`
</Accordion>

<Accordion title="Local PostgreSQL">
```bash
docker network create scribe-network

docker run -d \
  --name scribe-postgres \
  --network scribe-network \
  -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=your_password \
  -e POSTGRES_DB=scribe \
  -p 5432:5432 \
  postgres:latest
```

Then run Scribe Lite with `--network scribe-network` and `DB_HOST=scribe-postgres`.
</Accordion>
